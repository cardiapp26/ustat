Privacy Policy

Last updated: 2026-07-27 · Version 1.1

1. Who we are

uSTAT is a free, browser-based statistical analysis platform created and operated by Dr. Yusuf Hoşoğlu. Contact: contact@drtr.uk.

2. What data we receive

  • The file you choose to upload (CSV, Excel, SPSS, SAS, Stata, or JSON session).
  • The HTTP request metadata your browser sends: IP address, user agent, referrer, timestamp, requested URL.
  • The analysis parameters you submit through the UI (e.g. selected variables, knot counts, group columns).

3. How your data is processed

All statistical computation happens on the uSTAT server, not in your browser. When you upload a file:

  • It is parsed in RAM by the backend and bound to a session identifier (session_id).
  • It is never written to disk. The dataframe lives only in process memory. (Self-hosters have an opt-in setting, SESSION_DISK_CACHE=1, that snapshots sessions to a volume so they survive a restart. It is off by default and off on this instance.)
  • It is automatically cleared from memory 30 minutes after your last activity — enforced by a reaper thread that runs every 30 seconds regardless of traffic, so the limit holds on an idle server too. The operator can shorten it with the SESSION_TTL_SECONDS environment variable (default 1800; see backend/services/store.py).
  • If the server is restarted, all in-memory data is lost — there is no persistent storage.

The browser-side React app uses zustand for transient UI state. For your convenience it also keeps a local autosave so you can resume after a reload or crash:

  • A snapshot of your session — including the uploaded data — is written to your browser's own IndexedDB (the Recent sessions list on the home screen). Only the most recent sessions are kept, up to a small size limit; older ones are evicted automatically.
  • A service worker may cache API responses and the app shell so the tool loads quickly and works offline.
  • This storage lives only on your device — it is never uploaded anywhere beyond the server processing already described above, and we cannot see it.
  • It is not cleared merely by closing the tab. To remove it, delete entries from the Recent sessions list, or clear this site's data in your browser settings (which also unregisters the service-worker cache). A private/incognito window leaves nothing behind.

No cookies are used for your data, and nothing is sent to third parties.

4. What we log

  • Web server access log: standard HTTP metadata (IP, path, status, timestamp). These are the container's standard output, captured by the host's log driver on the server the instance runs on. They are not shipped to any third party. Retention is whatever the host is configured to keep — uSTAT sets no fixed period. The log records the request line, so column names passed as URL parameters (e.g. ?column=HbA1c) do appear in it. Cell values do not: the dataset is uploaded as a request body and analysis parameters are sent as JSON bodies, neither of which is logged.
  • Code runner audit log (only when ENABLE_CODE_RUNNER=1): timestamp, IP, session_id, SHA-256 prefix of the submitted code, first 200 characters, duration, exit code. Your dataset is never logged.

uSTAT loads no third-party analytics, advertising, or visitor-tracking scripts.

5. What we do NOT do

  • We do not sell or share your data.
  • We do not have user accounts, profiles, or persistent identifiers.
  • We do not use advertising trackers or third-party analytics of any kind.
  • We do not run automated decision-making or profiling.

6. Data subject to regulation

uSTAT is not HIPAA, GDPR, or ISO 27001 certified. Do not upload Protected Health Information (PHI), personally identifiable information (PII), or any data whose handling is restricted by law or by your institution. Anonymise datasets before upload: strip names, MRNs, dates of birth, and free-text identifiers. For regulated workflows, request a self-hosted or local-only build via email.

7. Your rights

Because we hold no persistent user data, the standard GDPR access / portability / erasure rights have nothing to act on once your session expires. If you wish to delete a session immediately, close the tab — the backend will discard it within 30 minutes of inactivity.
